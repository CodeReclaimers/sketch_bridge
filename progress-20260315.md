# Progress Log — 2026-03-15

## Auto-start COM adapter servers for SolidWorks and Inventor

**File modified:** `sketch_bridge/cad/manager.py`

**Summary:** SketchBridge previously required users to manually launch separate Python XML-RPC adapter servers for SolidWorks and Inventor before starting the application. These adapters bridge Python to the CAD applications via COM (since neither SolidWorks nor Inventor has a built-in Python environment, unlike FreeCAD). Users had to know to run `python -m morphe.adapters.solidworks.server` or equivalent, which was a significant UX friction point.

**What changed:** `CADManager.__init__` now auto-starts the SolidWorks and Inventor adapter servers on Windows via `start_server(blocking=False)` from the `morphe` library. The servers run on background threads within the SketchBridge process. On shutdown (`stop_monitoring`), any servers we started are cleanly stopped.

**Key design decisions:**
- **Platform gating:** Only attempted on `sys.platform == "win32"` since COM is Windows-only.
- **pywin32 availability check:** Each adapter exposes a `*_AVAILABLE` flag set at import time; we check per-adapter rather than globally.
- **Lazy COM connection is the key enabler:** The morphe servers don't connect to COM at startup — they do it per-RPC-request via `GetActiveObject()`/`Dispatch()`. This means the server can be running before the CAD application is open. When the user starts the CAD app later, the existing 5-second polling loop in `_check_connections` naturally detects it within one cycle.
- **Port conflict tolerance:** If the user is already running the server externally, `start_server()` gets an `OSError` on bind and returns `False`. We log it and move on — no conflict.
- **Alternatives considered:** Launching the servers as subprocesses was rejected because in-process background threads are simpler to manage (lifecycle tied to SketchBridge, no orphan processes) and `start_server(blocking=False)` already supports this pattern.

**No changes needed to the polling loop** — the existing `_check_connections` mechanism (5-second QTimer, ThreadPoolExecutor ping) handles the "CAD started after SketchBridge" case with no modifications.
